# upaffe v0.1.1

This update hardens first installation and HTTPS proxy operation for the
single-operator monitoring MVP.

## Changes since v0.1.0

- Initial setup now runs through the host-authorized `upaffe bootstrap`
  container command. It creates the operator and first management credential
  together. The public `POST /api/bootstrap` endpoint and its proof grant were
  removed. A local `recover-credential` command can replace a named management
  credential when its output is lost.
- The production PostgreSQL health check allows two minutes for a cold database
  initialization before failed probes count. This also covers fresh restore
  volumes.
- A Caddy reverse-proxy example protects secret report paths in both access
  and proxy error logs and replaces client-supplied forwarding information.
  The production guide explains the loss of proxy failure logs and how to
  handle an exposed report URL.
- The application warns when forwarded headers arrive from a peer outside the
  configured trusted proxy addresses. The warning is limited to once per
  minute and contains no forwarded header values or request path.
- Release publication can recover an interrupted tagged run without moving its
  tag or replacing an already verified image.

## Install and upgrade

Use the [production installation and update guide](https://github.com/datavisionzero/upaffe/blob/v0.1.1/docs/operations.md)
and deployment files from this tag. New installations need the local bootstrap
command; there is no public bootstrap write request. Existing v0.1.0 operators
and credentials remain after upgrade. Back up the database first: an older
image cannot open a database with migrations from this release.

Pin `ghcr.io/datavisionzero/upaffe:v0.1.1` by the digest recorded in the release
assets. Download the `ua_0.1.1_PLATFORM.zip` archive for Linux or macOS and
verify it with `SHA256SUMS` before use. The [CLI guide](https://github.com/datavisionzero/upaffe/blob/v0.1.1/docs/cli.md)
describes installation and credentials.
