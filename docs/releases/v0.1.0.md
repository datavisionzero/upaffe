# upaffe v0.1.0

The first complete MVP release provides self-hosted HTTP and push monitoring for a single operator. The web application and standalone `ua` CLI use the same API and administration rules.

## Included

- HTTP checks with bounded public targets, failure thresholds, incident history, and scheduled or immediate tests.
- Push reports for job completion and state, including explicit failures, missing-report deadlines, and monitor-scoped rotating credentials.
- Per-project email recipients, durable alert and recovery delivery, retry status, and timed project or monitor maintenance.
- An instance dashboard and one-call project report showing failures, freshness, maintenance, and delivery trouble.
- A Compose deployment with mounted secret files, PostgreSQL persistence, backup, update, isolated restore, and optional independent heartbeat monitoring.

## Operating limits

This is a single-operator release. The operator supplies an SMTP relay and an HTTPS reverse proxy for public access. Backups are run by the operator; upaffe does not schedule them. Completed monitoring and delivery history is retained for 90 days under the documented open-incident exceptions. A live or ready HTTP response alone does not prove that monitoring workers are progressing; use `/api/health/progress` and an independent checker or the optional outbound heartbeat.

## Install and upgrade

Use the [production installation and update guide](https://github.com/datavisionzero/upaffe/blob/v0.1.0/docs/operations.md). Pin the application image `ghcr.io/datavisionzero/upaffe:v0.1.0` by the digest recorded below. Download the `ua_0.1.0_PLATFORM.zip` archive for a supported Linux or macOS architecture and verify it with `SHA256SUMS` before running it. See the [CLI guide](https://github.com/datavisionzero/upaffe/blob/v0.1.0/docs/cli.md) for credentials and commands.

Back up the database before updating. An older application image cannot open a database with migrations from a newer release; use the documented backup and isolated restore procedure when recovery is needed.

The first release does not include public status pages, multi-user administration, a host agent, log collection, or automatic remediation.
