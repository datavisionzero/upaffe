# upaffe v0.5.0

This release makes monitoring inventories and evidence the first thing an
operator sees in the web interface, and moves creation, configuration, and
instance email administration into focused workflows.

## Changes since v0.4.0

- Project HTTP and push monitor routes now open on their inventories. The page
  header names the inventory and carries a `New HTTP monitor` or `New push
  monitor` action; monitor names link to their details, a failed read offers
  retry, and an empty inventory explains the monitor type and offers creation.
- Monitors are created on the focused routes `/projects/:key/new-http-monitor`
  and `/projects/:key/new-push-monitor`, with field-level errors, pending
  feedback, Cancel, and unsaved-input protection. Success opens the new
  monitor. The HTTP form still clears the target URL and secret header values
  as soon as they are sent; the push reporting credential is still issued once
  from the monitor detail.
- HTTP and push monitor details now show current state and latest evidence,
  check or report history, incidents, and email delivery before maintenance,
  secret headers or the reporting credential, and removal. An administration
  row links to each control. Configuration is edited on the focused route
  `/projects/:key/{http,push}-monitors/:monitor/edit`, with version-conflict
  reload, Cancel, and unsaved-change protection.
- Instance email settings are divided into task routes with local navigation.
  `/settings/email` shows delivery evidence and is where the dashboard link
  lands; relay settings, the write-only SMTP password, default recipients, and
  test send each have their own route, and saving the relay or replacing its
  password links directly to the test task.
- The cross-project monitor inventory distinguishes an instance without
  projects, one without monitors, an empty filtered project, and filters with
  no match, and offers project creation, monitor creation in a chosen project
  and type, or a filter reset. Pagination appears only when there is more than
  one page.
- Fixed: a newly created live project could appear in the Live project
  inventory as deleted, with an invalid date, a Restore action, and no link to
  open it. The web client now treats values the API omits as absent, which also
  removes a spurious "Load older" action on the last page of monitor history.
- Focused creation and edit routes, including `/projects/new`, keep one
  readable column on wide screens. Visual, keyboard, and WCAG 2A/AA coverage
  includes every new route.

Existing monitor detail links, including incident email links, keep working.
The release changes the web interface only. Monitoring, incident, maintenance,
email-delivery, API, and CLI behavior remain compatible with v0.4.0, and there
is no database migration.

## Install and upgrade

Use the [production installation and update guide](https://github.com/datavisionzero/upaffe/blob/v0.5.0/docs/operations.md)
and deployment files from this tag. Back up the database before updating.

Pin `ghcr.io/datavisionzero/upaffe:v0.5.0` by the digest recorded in the release
assets. Download the `ua_0.5.0_PLATFORM.zip` archive for a supported Linux or
macOS architecture and verify it with `SHA256SUMS` before use. The [web UI
guide](https://github.com/datavisionzero/upaffe/blob/v0.5.0/docs/ui.md)
documents the resulting routes and workflows.
